# Sega SG-1000 sources

Per-tree catalogue for `data/sg1000`. The rules that apply everywhere — never
construct a URL, the ROM-hosting link ban, dump identity, titles, publishers,
cover art, licensing — are in [`README.md`](README.md).

The tree covers the SG-1000 console library, including the Tsukuda Original
Othello Multivision line (SG-1000-compatible hardware) and the unlicensed
Taiwanese releases. SC-3000 computer software (`.sc` dumps, BASIC carts,
SF-7000 programs) is not yet imported: the emulator's SG-1000 core will grow
SC-3000 support, and that software joins this tree when it can run.

## Titles

Most licensed releases are Japanese; boxes typically set the title in Latin
script alongside Japanese, and that boxed English name is the entry title.

**The game title is English or a Latin transliteration; a foreign release's
own title is written in its native script** (Andrew, 2026-08-28). So the entry
stays `Bomber Man Special` while its two Taiwanese releases carry `爆破隊` and
`轟炸隊`, Bank Panic's Taiwanese release carries `比利大盜`, and Bomb Jack's
Korean one carries `범짹`. Earlier entries wrote these romanized (The Castle /
`Mowang migong`) — convert them to native script as each game is curated.

**MAME's software list is the source for the native title**, and the only one
an agent can read: each `<software>` carries
`<info name="alt_title" value="爆破隊 ~ Bàopò duì"/>`, giving the characters
beside the pinyin, keyed by dump. Look the hash up rather than reconstructing
characters from a romanization — pinyin maps to many possible hanzi, and
Taiwanese carts use traditional forms. Where a logo-variant pair exists, MAME
names each build after the logo it actually shows (`Chaoren` vs `Bomb Jack`),
which is how to tell which release carries the native title. A No-Intro multi-region tag
(`Japan, Australia`, …) is one dump's distribution, not evidence of distinct
carts — keep one release unless a source shows a distinct release.

## Sega Retro game pages

Every game gets its Sega Retro article as a `Sega Retro` link, the way the VCS
tree carries an `AtariAge` page beside its Compendium `Manual` — the wiki is
this library's per-game reference for publisher, date, model number and
alternate titles. Article URLs are plain MediaWiki page titles:
`https://segaretro.org/<Page_Title>` with spaces as underscores (e.g.
`segaretro.org/Champion_Ice_Hockey`, `segaretro.org/OM-G001`).

Those per-country lists also carry each release's **catalogue number**
(`G-1033`, `C-33`, `OM-G008`). **The database stores no catalogue number and
should not gain a field for one** (Andrew, 2026-08-28): only official
commercial releases have them, and they say nothing about how a game plays.
Use them as a *research* tool and leave the receipt in chat:

- **Card vs cartridge.** A `G-10nn` cartridge and a `C-nn` card with matching
  digits are the same game sold twice — Champion Boxing `G-1033`/`C-33`,
  Champion Golf `G-1005`/`C-05`, Monaco GP `G-1017`/`C-17`, Star Force
  `G-1043`/`C-43`, Zippy Race `G-1026`/`C-26`. That is a real release split,
  corroborated by separate `…Card…`/`…Cart…` manual scans and TOSEC's own
  `[Card]`/`[Cartridge]` tags. `OM-G` numbers are Othello Multivision.
- **One product or several.** The same number across Japan, Australia, France
  and Italy means one product went to every market — the evidence behind the
  `tv_format` rule below.

**Take the page title from a saved `Category:SG-1000 games` listing, never from
the game's title or slug.** Sega Retro's naming diverges from ours in ways no
rule predicts — `Champion Kendo` for our `champion-kendou`, `Sannin Mahjong`
for `san-nin-mahjong`, `Black Onyx` for `The Black Onyx` — and an agent cannot
fetch the result to check it.

## Taiwanese MSX1 conversions

A large part of the unlicensed Taiwanese library is not a Sega release at all
but an **MSX1 game converted to the SG-1000** — the two machines share a Z80
and a TMS9918, so a port is cheap. These carts appear on **no** Sega Retro
country list (those cover official releases), which is the quickest way to
spot one; Sega Retro does still keep a page for many of them.

MAME's software list carries the identification in a comment block beside the
entries, giving serial, native title and the MSX original:

| Serial | Native title | Converted from | Our slug |
|--------|--------------|----------------|----------|
| R-101 | 奧運二代 | Hyper Sports 2 | `hyper-sports-2` |
| R-102 | 魔鬼樹 | Magical Tree | `magical-tree` |
| R-103 | 功夫 | Yie Ar Kung-Fu | `yie-ar-kung-fu` |
| R-104 | 娃娃歷險 | Cabbage Patch Kids | `cabbage-patch-kids` |
| Y-106 | 金字塔 | King's Valley | `jinzita` |
| R-108 | 乒乓球 | Konami Ping Pong | `ping-pong` |
| R-112 | 馬戲團 | Circus Charlie | `circus-charlie` |
| Y-116 | 魔王迷宮 | The Castle | `the-castle` |

The same block notes two Aaronix carts holding a regular Japanese build under
a Chinese label (A103 大金鋼 = Congo Bongo, A116 世界賽車 = Monaco GP, the
latter the same dump as B-017), and warns that carts dumped by Bock have no
known manufacturer, so licensed and pirate cannot be told apart.

Curating one: the entry title is the **original game's** English name, the
release carries the **native** Chinese title, and the publisher is whoever the
softlist names (often Aaronix, sometimes unknown — leave it empty rather than
guess). Entries still filed under a romanised Chinese name — `jinzita` is
King's Valley — get retitled as they come up. Describe the game from the
original's sources; say in chat that the conversion is unverified against them.

## Manuals

Most of the licensed library has a scanned manual, and it is the best source
this tree has for gameplay: it documents *this* cart, where an encyclopaedia
article usually documents a multi-platform game as a whole. Where the two
disagree about a mechanic, the manual wins — 007 James Bond's Wikipedia
article says "shots and flare bombs", while the cart's own manual names an
anti-air beam and a depth charge.

Order of preference: **Sega Retro** → **gamesdatabase.org** → **archive.org
`sg1000manuals`**. The first two are vetted and linkable; the third is a last
resort Andrew allowed for manuals only (see the table above).

**Only fall through to archive.org once Sega Retro has actually been ruled
out — which an agent cannot do alone.** An agent cannot read Sega Retro, and
search does not reliably surface what it holds, so "Sega Retro has no manual
for this game" is a claim only Andrew can make. Ask; do not infer it from a
failed search.

**Sega Retro file URLs are constructible from the file name**, so a category
listing is all that is needed — the hex folders are not arbitrary. MediaWiki
stores an upload at `images/<h[0]>/<h[0:2]>/<name>` where `h` is the MD5 of
the file name with spaces as underscores. Verified against two known files:
`Bank_Panic_SG-1000_JP_Manual.pdf` hashes to `09` and lives at `images/0/09/`,
`007_James_Bond_SG1000_JP_Manual.PDF` hashes to `57` and lives at
`images/5/57/`.

```python
import hashlib
h = hashlib.md5(name.encode()).hexdigest()
url = f"https://segaretro.org/images/{h[0]}/{h[:2]}/{name}"
```

Take the name **exactly** as the category lists it: Sega Retro is inconsistent
about `SG-1000` vs `SG1000` and `.pdf` vs `.PDF`, and one wrong character
gives a different hash and a dead link. An agent cannot fetch the result to
check it, so a mistranscribed name yields a plausible-looking broken URL —
the file name has to come from the category page, not from memory or a guess
at the pattern.

Japanese manuals are readable as page images through the Read tool once the
PDF is downloaded. Record the language on the link (`languages: [Japanese]`),
since most are Japanese-only.

## Cartridge boards

The SG-1000 cart carries no header, so the board is a database fact or
nothing (`cart_type`; absent = plain ROM). The emulator's vocabulary:
`FLAT`, `OTHELLO` (Sega 2 KB RAM), `CASTLE` (Sega 8 KB RAM), and the two
Taiwanese pass-through expanders `DAHJEE-A` and `DAHJEE-B`. The MAME software
list is the board source; every known RAM-bearing cart was seeded from it.
A game that boots to garbage or hangs in playtest with no board stated is
the classic symptom of a missing `cart_type`.

**A 40960-byte dump is a memory map, not the ROM and not an overdump.**
SMS Power! calls these "40k map" dumps, and TOSEC tags them `[40K]` (once
`[40K map]`): they are a read of the console address space `$0000-$9FFF`
rather than of the ROM chip, whose real size is 16 KB. Measured across seven
of them, the first 32 KB is one 8 KB block mirrored four times (Congo Bongo:
a 16 KB block twice) and `$8000-$9FFF` holds different content again — the
cart answering `/EXM1` as well as `/EXM2`. Say so on the artifact
(`label_artifact`, e.g. "40 KB memory map"), because the byte count otherwise
reads as a 40 KB cartridge. It is not a `defect`: nothing is padded,
truncated or corrupt, so neither `Overdump` nor `BadDump` fits.

Such a map is not the same build as the plain 16 KB dump beside it. The
40 KB Yamato differs from the 16 KB one in exactly twelve bytes, every one an
address high byte moved by +$60 (`$20xx-$38xx` becomes `$80xx-$98xx`) —
matching where the second 8 KB is decoded. Two carts wiring one 16 KB ROM
differently, not one cart dumped twice.

They need no `cart_type`: 40960 is not a power of two, so the `FLAT` board
indexes the image directly and replays the captured decode. **That
correctness is a property of the dump, not of the board model** — a proper
16 KB chip dump of the same cart would put the second half at `$2000` and
break, and the vocabulary has no board that decodes ROM into both windows.
Naming that board is open work; the `OM-Gnnn` model numbers and MAME's
`hash/sg1000.xml` are where to look.

Boards the emulator names but does not build: Terebi Oekaki's drawing
tablet, the SC-3000 Survivors multicarts, and the BASIC carts. Their dumps
stay catalogued as what they are; flag playability, don't invent a board.

## TV standard

**The dump decides the standard, not the market (Andrew, 2026-08-28).** A
European or Oceanian release that ships the *same ROM* as the Japanese one
stays `Ntsc` — it is the Japanese program, sold abroad. Only a **separate
release with its own dump** is tagged `Pal`. So the question to ask is never
"was it sold in Italy" but "is there a distinct dump for that market".

The practical test is the **catalogue number**: Sega Retro's per-country lists
give one, and where Japan, Australia, France and Italy all show the *same*
number (N-Sub `G-1003`, Congo Bongo `G-1007`, Yamato `G-1008`, Safari Race
`G-1032`), one product went to every market — `Ntsc`, and one release, not
five. TOSEC agrees where it tags a dump `(EU-JP)`: one dump, both markets.

The console fixes the standard — TMS9918A machines are NTSC, TMS9929A
machines PAL — so unlike the VCS there are no per-standard dumps, and no
probe can read a standard off a ROM. What `tv_format` states is which
machine the software was written against: the presentation its home market
saw. It is recorded explicitly on every release, as the VCS records its —
absent means unstated, never "NTSC by default". The import derives it from
the release's markets (Japan/Taiwan/Korea sold NTSC machines; a
PAL-market-only set is PAL-authored); correct it per release where a source
shows the derivation wrong. 21 of the tree's games were also sold in
Australia, France, Italy or New Zealand (Sega Retro keeps a per-country list
for each), but on the shared-catalogue-number evidence those were the same
product, so they stay `Ntsc` and need no release of their own. France is
SECAM, the rest of those markets PAL. A
50 Hz-authored program run at 60 Hz is 20% fast and may overrun its vblank
transfer budget — real misbehaviour, which is why the fact is worth
recording.
