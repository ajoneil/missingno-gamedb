# Sega SG-1000 sources

Per-tree catalogue for `data/sg1000`. The rules that apply everywhere — never
construct a URL, the ROM-hosting link ban, dump identity, titles, publishers,
cover art, licensing — are in [`README.md`](README.md).

The tree covers the SG-1000 console library, including the Tsukuda Original
Othello Multivision line and the unlicensed Taiwanese releases. SC-3000 computer
software is not yet imported: it joins this tree when the core can run it.

## Titles

Most licensed releases are Japanese, and boxes typically set the title in Latin
script alongside Japanese; that boxed English name is the entry title.

**The entry title is English or a Latin transliteration; a foreign release's own
title is written in its native script**, never romanised. Where a catalogue
offers only a romanisation, the release title stays empty until the hangul or
hanzi turns up.

**MAME's software list is the source for native titles**, and the only one an
agent can read: look the dump's hash up rather than reconstructing characters
from a romanisation, since romanisations map to many possible characters and
Taiwanese carts use traditional forms. Where a logo-variant pair exists, MAME
names each build after the logo it draws, which is how to tell which release
carries the native title. A No-Intro multi-region tag is one dump's
distribution, not evidence of distinct carts.

## Sega Retro

Every game gets its article as a `Sega Retro` link — the wiki is this library's
per-game reference for publisher, date, model number and alternate titles.
Article URLs are plain MediaWiki page titles with spaces as underscores.

**Take the page title from a saved category listing, never from the game's title
or slug.** Sega Retro's naming diverges from ours in ways no rule predicts, and
an agent cannot fetch the result to check it. Its country lists are also not a
complete index of what the wiki holds, so a game missing from a listing is not a
game missing from Sega Retro — the unlicensed Taiwanese carts are the systematic
case, appearing on no country list yet keeping pages, filed under the original
game's English name.

Those listings also carry each release's **catalogue number**. **The database
stores no catalogue number and should not gain a field for one** — only official
commercial releases have them and they say nothing about how a game plays. Use
them as a research tool and leave the receipt in chat:

- **Card vs cartridge.** A cartridge and a card with matching digits are the same
  game sold twice — a real release split, corroborated by separate manual scans
  and by TOSEC's own `[Card]`/`[Cartridge]` tags.
- **One product or several.** The same number across several markets means one
  product went to all of them: one release, not several.

## Taiwanese MSX1 conversions

Much of the unlicensed Taiwanese library is not a Sega release but an **MSX1 game
converted to the SG-1000** — the two machines share a Z80 and a TMS9918, so a
port is cheap. Appearing on no Sega Retro country list is the quickest way to
spot one. MAME's software list carries the identification in a comment block
beside the entries, giving serial, native title and the MSX original, and it also
maps Taiwanese serials to their Sega originals; **read that table rather than
inferring from the digits**, which mirror for a while and then stop. The block is
not exhaustive — when a cart is missing from it, search the entries for its hash.

Curating one: the entry title is the **original game's** English name, the
release carries the **native** title, and the publisher is whoever the softlist
names — left empty rather than guessed. Describe the game from the original's
sources and say in chat that the conversion is unverified against them.

## Manuals

Most of the licensed library has a scanned manual, and it is the best gameplay
source this tree has: it documents *this* cart, where an encyclopaedia article
documents a multi-platform game as a whole. Where the two disagree about a
mechanic, the manual wins.

**Sega Retro file URLs are constructible from the file name**, so a category
listing is all that is needed — MediaWiki stores an upload at
`images/<h[0]>/<h[0:2]>/<name>` where `h` is the MD5 of the file name with spaces
as underscores:

```python
import hashlib
h = hashlib.md5(name.encode()).hexdigest()
url = f"https://segaretro.org/images/{h[0]}/{h[:2]}/{name}"
```

Take the name **exactly** as the category lists it — the wiki is inconsistent
about `SG-1000` vs `SG1000` and `.pdf` vs `.PDF`, and one wrong character gives a
different hash and a dead link an agent cannot check.

Two cautions. **A category listing is not a complete index of the manuals it
names**, and a file name may spell the title differently from the game, so a
search on our title can miss one that exists. And **the file name does not tell
you what is inside**: a name is never evidence for the `languages` tag or for
which market a manual documents — that comes from reading it. Japanese manuals
are readable as page images once the PDF is downloaded; record the language on
the link.

**Only fall through to archive.org once Sega Retro has actually been ruled out —
which an agent cannot do alone.** Ask; do not infer it from a failed search.

## Cover art

README.md's hosts come first — Hasheous, then libretro-thumbnails — but both
serve this library badly, so expect to fall through. **Hasheous groups the cart
under the arcade record** for any game Sega also put in an arcade, so what it
returns is the coin-op flyer; look at what `cover_candidates` returns and drop a
flyer rather than staging it. libretro-thumbnails has almost no SG-1000 boxart.

Sega Retro box scans are the useful addition, by the same path rule as the
manuals — but **the file name is not predictable**, and a page may hold several
fronts of very different scan quality. So a cover URL comes from a human, and a
guessed name yields a plausible-looking dead link.

## Cartridge boards

The cart carries no header, so the board is a database fact or nothing
(`cart_type`; absent = plain ROM). MAME's software list is the board source. A
game that boots to garbage or hangs with no board stated is the classic symptom
of a missing `cart_type`.

**A 40960-byte dump is a memory map, not the ROM and not an overdump.** It is a
read of the console address space rather than of the ROM chip: the low region is
one block mirrored several times, and the top holds different content again,
the cart answering both expansion selects. Record it as `defect: MemoryMap` with
a label saying so, because the byte count otherwise reads as a 40 KB cartridge.
`MemoryMap` exists because neither `Overdump` nor `BadDump` fits — nothing is
padded, truncated or corrupt.

**State the silicon as the board's `rom`, measured rather than assumed.** Mirrors
are not ROM: measure each dump's block structure before stating a size, since
maps of the same length can hold different amounts of real silicon. Such a map is
also not the same build as a plain dump beside it — the decode differs, so the
address bytes do too. They need no board of their own: the length is not a power
of two, so the plain board indexes the image directly and replays the captured
decode. **That correctness is a property of the dump, not of the board model** —
a proper chip dump of the same cart would break, and the vocabulary has no board
that decodes ROM into both windows. Naming that board is open work.

Boards the emulator names but does not build: the drawing tablet, the multicarts
and the BASIC carts. Their dumps stay catalogued as what they are; flag
playability, don't invent a board.

## TV standard

**The dump decides the standard, not the market.** A European or Oceanian release
shipping the *same ROM* as the Japanese one stays `Ntsc` — it is the Japanese
program, sold abroad. Only a **separate release with its own dump** is tagged
`Pal`. The question is never "was it sold there" but "is there a distinct dump
for that market".

The practical test is the **catalogue number**: where several countries show the
same number, one product went to every market — one release, `Ntsc`. TOSEC
agrees where it tags a dump for both markets at once.

The console fixes the standard — TMS9918A machines are NTSC, TMS9929A PAL — so
unlike the VCS there are no per-standard dumps and no probe can read a standard
off a ROM. What `tv_format` states is which machine the software was written
against: the presentation its home market saw, recorded explicitly on every
release, absent meaning unstated rather than "NTSC by default". The import
derives it from the release's markets; correct it per release where a source
shows the derivation wrong. A 50 Hz-authored program run at 60 Hz is 20% fast and
may overrun its vblank budget, which is why the fact is worth recording.
